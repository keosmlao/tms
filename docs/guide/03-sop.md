## 📌 SOP-1 · ພະນັກງານ Office / Dispatch

### 1.1 ຈຸດປະສົງ
ຈັດຖ້ຽວ, ສ້າງໃບງານ, ຕິດຕາມ ແລະ ປິດງານໃຫ້ຖືກຕ້ອງ ຄົບຖ້ວນ ທັນເວລາ.

### 1.2 ຄວາມຮັບຜິດຊອບປະຈຳວັນ (Checklist)
- [ ] **08:00 - ຕົ້ນວັນ:** ເປີດໜ້າ *ລໍຖ້າຈັດຖ້ຽວ*, ກວດບິນທັງໝົດທີ່ຮັບເຂົ້າມາຈາກ ERP.
- [ ] **ຈັດຖ້ຽວ:** ກຳນົດ ວັນສົ່ງ · ຮອບການຈັດສົ່ງ · ເສັ້ນທາງ ໃຫ້ແຕ່ລະບິນ; ຈັດບິນທາງດຽວກັນເຂົ້າໃບງານດຽວກັນ.
- [ ] **ສ້າງໃບງານ:** ຈັບຄູ່ ລົດ + ຄົນຂັບ ໃຫ້ເໝາະກັບນ້ຳໜັກ/ປະລິມານບັນຈຸ.
- [ ] **ສົ່ງອະນຸມັດ:** ກວດຄວາມຖືກຕ້ອງກ່ອນ ແລ້ວກົດສົ່ງໃຫ້ຫົວໜ້າອະນຸມັດ (SLA < 2h).
- [ ] **ຕິດຕາມ:** ຕະຫຼອດວັນ ເຝົ້າເບິ່ງບິນຄ້າງຢູ່ແຕ່ລະສະຖານະ ແລະ ຕິດຕາມຕຳແໜ່ງ GPS.
- [ ] **ກວດຮັບປິດງານ:** ຫຼັງຄົນຂັບປິດງານ ກວດຫຼັກຖານຮູບ/ຈຳນວນ ກ່ອນກົດ *ປິດສຳເລັດ*.
- [ ] **17:00 - ທ້າຍວັນ:** ອອກ *ລາຍງານປະຈຳວັນ*, ສະຫຼຸບບິນຄ້າງ ແລະ ຜົນງານສົ່ງໃຫ້ຫົວໜ້າ.

### 1.3 ກົດລະບຽບປະຕິບັດ (Must Rules)
> ⚠️ **MUST:** ຫ້າມສ້າງໃບງານທີ່ນ້ຳໜັກ/ປະລິມານເກີນຄວາມສາມາດບັນຈຸຂອງລົດ.
> ⚠️ **MUST:** ທຸກການ **ຍົກເລີກບິນ** ຕ້ອງມີເຫດຜົນ ແລະ ຜ່ານການອະນຸຍາດຈາກຫົວໜ້າ.
> ⚠️ **MUST:** ບໍ່ປ່ອຍໃຫ້ບິນຄ້າງຢູ່ສະຖານະໃດໜຶ່ງເກີນ SLA ໂດຍບໍ່ຕິດຕາມ.

## 📌 SOP-2 · ຫົວໜ້າ / ຜູ້ຄຸມ (Supervisor)

### 2.1 ຈຸດປະສົງ
ຄວບຄຸມຄຸນນະພາບການຈັດສົ່ງ ຜ່ານການອະນຸມັດໃບງານ, ຕິດຕາມ realtime ແລະ ບໍລິຫານ KPI.

### 2.2 ຄວາມຮັບຜິດຊອບປະຈຳວັນ
1. **ອະນຸມັດໃບງານ (`/approvals/pending`):** ກວດສອບຄວາມເໝາະສົມຂອງລົດ/ຄົນຂັບ, ນ້ຳໜັກ, ເສັ້ນທາງ. ກົດອະນຸມັດ ຫຼື ຕີກັບ ພາຍໃນ **SLA < 2 ຊົ່ວໂມງ**.
2. **ຕິດຕາມ Realtime:** ໃຊ້ *ແຜນທີ່ລົດ / ແຜນທີ່ມືຖື* ເບິ່ງຕຳແໜ່ງລົດທີ່ກຳລັງແລ່ນ.
3. **ຕິດຕາມ KPI:** ກວດລາຍງານປະຈຳວັນ (ສົ່ງສຳເລັດ/ວັນ, ຄ້າງ/ວັນ, Leaderboard ຄົນຂັບ).
4. **ຈັດການເຫດການ (Exception Handling):** ແກ້ໄຂບິນຄ້າງນານ, ບິນສົ່ງບໍ່ຄົບ ຫຼື ລົດແລ່ນຫຼຸດເສັ້ນທາງ.
5. **ພິຈາລະນາອະນຸຍາດ:** ອະນຸມັດຄຳຂໍຍົກເລີກ/ແກ້ໄຂບິນ ຈາກ Office.

### 2.3 ກົດລະບຽບປະຕິບັດ (Must Rules)
> ⚠️ **MUST:** ບໍ່ອະນຸມັດໃບງານທີ່ຂໍ້ມູນບໍ່ຄົບຖ້ວນ ຫຼື ນ້ຳໜັກເກີນ.
> ⚠️ **MUST:** ທຸກການຕີກັບ (Reject) ຕ້ອງລະບຸເຫດຜົນທີ່ຊັດເຈນ.

## 📌 SOP-3 · ຄົນຂັບລົດ (Driver)

### 3.1 ຈຸດປະສົງ
ຮັບ ແລະ ຈັດສົ່ງສິນຄ້າໃຫ້ຄົບຖ້ວນ ຖືກຕ້ອງ ພ້ອມຫຼັກຖານການສົ່ງ.

### 3.2 ຄວາມຮັບຜິດຊອບຕໍ່ 1 ຖ້ຽວ (Workflow Checklist)
1. **ກ່ອນອອກງານ:** Login ແອັບມືຖື, ເປີດ GPS **Allow all the time** + Notifications, ກວດ Battery.
2. **ຮັບຖ້ຽວ (`WI-C1`):** ກົດຮັບໃບງານທີ່ໄດ້ຮັບມອບໝາຍ.
3. **ເບີກເຄື່ອງ:** ຮັບສິນຄ້າຈາກສາງ, ກວດຈຳນວນສິນຄ້າ ແລະ ໃບບິນໃຫ້ຄົບ.
4. **ເລີ່ມຈັດສົ່ງ (`WI-C2`):** ກົດ *ເລີ່ມຈັດສົ່ງ* (GPS ຈະສົ່ງຕຳແໜ່ງ Realtime ອັດຕະໂນມັດ).
5. **ຮອດຈຸດສົ່ງ (`WI-C3`):** ກົດ *ເຊັກອິນ*, ມອບສິນຄ້າ, **ຖ່າຍຮູບຫຼັກຖານ** (ສິນຄ້າ + ລາຍເຊັນລູກຄ້າ), ກົດ *ສົ່ງບິນສຳເລັດ*.
6. **ກໍລະນີສົ່ງບໍ່ໄດ້ (`WI-C4`):** ກົດ *ສົ່ງຄືນ* ພ້ອມໃສ່ເຫດຜົນ ແລະ ຖ່າຍຮູບ (ຖ້າມີ).
7. **ບັນທຶກນ້ຳມັນ (`WI-C6`):** ເຕີມນ້ຳມັນ ➔ ປ້ອນເງິນ/ລິດ/ກິໂລແມັດ + ຖ່າຍຮູບໃບບິນ.
8. **ຈົບຖ້ຽວ (`WI-C8`):** ກົດ *ປິດງານ*.

### 3.3 ກົດລະບຽບປະຕິບັດ (Must Rules)
> ⚠️ **MUST:** ຫ້າມກົດ *ສົ່ງສຳເລັດ* ໂດຍບໍ່ມີຮູບຫຼັກຖານການສົ່ງ.
> ⚠️ **MUST:** ຫ້າມປິດ GPS ຫຼື ປິດ Location Services ຂະນະຈັດສົ່ງ.
> ⚠️ **MUST:** ຮູບຫຼັກຖານຕ້ອງແຈ້ງ ແລະ ຂະໜາດບໍ່ເກີນ 8MB/ຮູບ.

## 📌 SOP-4 · ຝ່າຍຂາຍ (Sales)

### 4.1 ຈຸດປະສົງ
ຕິດຕາມສະຖານະການຈັດສົ່ງໃຫ້ລູກຄ້າ ແລະ ປະສານງານແກ້ໄຂບັນຫາ.

### 4.2 ຄວາມຮັບຜິດຊອບ
1. **ຕິດຕາມບິນ:** ກວດເບິ່ງ *ບິນສົ່ງບໍ່ສຳເລັດ* ຂອງລູກຄ້າຕົນເອງ.
2. **ກຳນົດວັນຈັດສົ່ງ:** ປະສານ Office ຍ້າຍວັນ/ຮອບຈັດສົ່ງ ເມື່ອລູກຄ້າຮ້ອງຂໍ.
3. **ຕິດຕາມຄວາມພຶງພໍໃຈ:** ກວດເບິ່ງຄະແນນ 1-5 ດາວ ແລະ ຄຳຕິຊົມທີ່ `/rate`.

## 📌 SOP-5 · ຜູ້ດູແລລະບົບ (Admin)

### 5.1 ຈຸດປະສົງ
ຮັກສາຄວາມຖືກຕ້ອງຂອງ Master Data, ຄຸ້ມຄອງສິດຜູ້ໃຊ້ ແລະ ຮັບປະກັນ System Security.

### 5.2 ຄວາມຮັບຜິດຊອບ
1. **Master Data Management:** ຈັດການຂໍ້ມູນ ລົດ, ປະເພດລົດ, ພະນັກງານ, ເສັ້ນທາງ, ຮອບຈັດສົ່ງ.
2. **Access Control:** ທົບທວນສິດ 5 Roles (Office, Supervisor, Driver, Sales, Admin).
3. **Audit Logging:** ກວດ Audit Log ເປັນປະຈຳ ເພື່ອຕິດຕາມການປ່ຽນແປງຂໍ້ມູນ.
4. **Security & Backup:** ຮັບປະກັນ Database Backup ແລະ System Security.

## 🔒 ການກວດສອບ ແລະ ບັນທຶກ (Audit Logging)
- ທຸກການປ່ຽນສະຖານະບິນ ແລະ ການອະນຸມັດ ຖືກບັນທຶກໄວ້ໃນ **Audit Log**.
- ຫຼັກຖານການສົ່ງ (ຮູບ + ລາຍເຊັນ) ຖືກເກັບໄວ້ຢ່າງປອດໄພ.
- ຫົວໜ້າທົບທວນ KPI ປະຈຳອາທິດ/ເດືອນ ຈາກໝວດ *ລາຍງານ*.
